# 해담시청 민원포털 · React 프론트

시민의 목소리를 담다, 해담시청. 사용자 결정(2026-10-19): React + Flask. React 19, React Router 7, Vite 8. Node 22.12+ (검증 24.15.0), npm 11.12.1. 정확한 의존성은 package-lock.json으로 잠근다. 담당: B + Codex, 독립 리뷰어 별도 배정.

## 준비와 실행

```powershell
npm ci
npm run build
```

백엔드 저장소를 형제 폴더 `haedam-portal-backend`에 둔 뒤 그곳의 `tools/start.ps1 -Setup -SeedDemo`를 실행하면 실제 API와 이 dist를 `http://127.0.0.1:5000`에서 함께 제공한다. 기존 DB에는 SeedDemo를 반복하지 않는다. React 화면만 성공 데이터로 대체하는 합성 모드는 없다.

개발 중에는 백엔드를 5000에서 실행한 채 `npm run dev`, `http://127.0.0.1:5173`을 사용한다. Vite 개발 프록시는 `/api`만 전달하며 프록시 배포를 추가하지 않는다. 최종 빌드는 Flask가 제공한다. 정적 파일 배포는 dist의 실제 경로를 C에게 전달하고 승인한 배포 기준본·해시·FIM 규칙을 별도로 맞춘다.

## 화면과 동작

- `/`: 해담시청 안내, 분야별 신청, 실제 최근 민원, 이용 절차·FAQ.
- 시민·비로그인 홈에서는 ‘상황으로 찾기’에서 생활 문제6가지의 추천 분야/작성 요령을 보고 신청할 수 있다. 기존 분야 카드는 ‘분야로 바로 신청’에서 제공한다. 로그인 전 선택도 유지되며 제목/본문/동의는 자동 입력하지 않는다. 신청서의 분야는 직접 바꿀 수 있고 모바일에서는 입력란 앞 ‘작성 요령 보기’를 펼쳐 안내를 확인한다.
- `/login`, `/register`: 로그인·시민 가입. 실패 원인을 안내하며 비밀번호를 저장하지 않는다.
- `/petitions`, `/petitions/new`, `/petitions/:id`: 본인 목록·상태 집계·검색·필터·페이징·신청·답변·타임라인.
- 민원 신청은 내용 작성→입력 내용 확인/수정→최종 접수 순서다. 확인만으로 전송하지 않는다. 시민은 `/petitions/:id?view=receipt`에서 서버에 저장된 접수 확인서를 조회·인쇄할 수 있다. 응답 유실로 저장 여부가 불명확하면 재전송을 중지하고 나의 민원 확인을 안내한다. 브라우저 재시작까지 포함한 서버 중복 접수 방지는 별도 과제다.
- `/work`: 담당자 미배정·내 민원 대기열. 본인 배정→처리 시작→답변과 처리 완료.
- 담당자 목록의 다음 행동은 상세의 처리/이력 영역으로 바로 연결하며 목록 조건을 유지한다. 상세에서는 신청 원문과 답변 패널을 함께 보고, 빈 답변에만 구성 틀을 넣을 수 있다. 답변 내용 확인/수정→실제 조치 확인→최종 등록 순서이며, 변경 충돌·응답 오류가 나면 초안을 보존하고 최신 상태부터 다시 조회한다. 초안은 브라우저 저장소에 저장하지 않는다.
- `/admin`: 계정 생성·권한 변경·잠금·오탐 해제(비밀번호 유지)·비밀번호 재설정, 설정된 관제 대시보드 링크. 오탐 해제는 잠긴 계정에서 대상 확인 후 수행하며 기존 세션은 복원하지 않는다. [S4 해제 인수](docs/S4-UNLOCK-2026-10-28.md).
- 관리자 권한·이용 상태 필터는 검색 결과 전체에 적용한다. 카드 숫자는 검색어에 맞는 전체 계정, 목록 건수는 권한·이용 상태까지 적용한 결과다. 검색/필터/페이지는 URL로 복원하며 저장으로 마지막 항목이 빠지면 실제 남은 페이지로 돌아간다. 새 집계 API가 없는 구 백엔드는 계약 오류로 표시하므로 백엔드를 먼저 적용한다. [관리자 조회 계약](docs/haedam/ADMIN-USERS-API.md)을 따른다.
- `/account`: 현재 계정과 비밀번호 변경. 변경 시 다른 세션 회수.

서버가 역할·소유권·담당 범위를 검사한다. 화면의 접근 제한만으로 권한을 보장하지 않는다. API 오류·연결 실패·인증 만료·로딩·빈 결과·중복 버튼 방지·모바일·키보드·본문 바로가기를 지원한다. 문자열은 React 텍스트로 출력하며 민원 원문을 HTML로 렌더링하지 않는다. 브라우저 저장소에 인증 정보·민원 데이터를 넣지 않는다.

## 검증

[웹 품질 구현 계획·WQ01~04 결과](docs/WEB-IMPLEMENTATION-2026-10-27.md)에 확인/수정·접수 확인서·인쇄의 변경과 검증 범위를 기록했다. 새로고침을 승인한 뒤의 초안 자동 복구는 제공하지 않으며 민원 원문을 브라우저 저장소에 저장하지 않는다.

```powershell
npm run build
npm run test:e2e
```

백엔드 `.venv`가 준비돼 있어야 한다. 테스트가 5005에서 일회용 SQLite 서버를 시작하고 끝나면 종료한다. 기존 5000 서버·DB를 사용하지 않는다. Windows의 Microsoft Edge를 기본 사용하며 다른 환경은 `PW_CHANNEL=chromium`과 Playwright Chromium 준비가 필요하다.

MySQL 브라우저 통합은 백엔드 폴더에서 `.\.venv\Scripts\python.exe tools/check_mysql_e2e.py`를 실행한다. Docker·이 프론트의 `npm ci`·Edge가 필요하며 실행기가 MySQL 생성·React 빌드·Waitress 실행·브라우저 전체 테스트·두 번의 프로세스 재시작·DB 감사·정리를 맡는다. 일반 SQLite 명령에서는 MySQL 전용 영속성 테스트를 제외한다. `HAEDAM_E2E_MYSQL`과 제어 경로를 직접 설정해 기존 서버에 붙이지 않고 전용 실행기를 사용한다.

실제 서버에서 시민 접수·새로고침·담당자 처리·시민 결과 확인, 가입·실패 후 재시도·타인 조회 거절·XSS 문자열·로그아웃, 관리자 계정 관리, 모바일 폭·키보드, 비밀번호 변경·네트워크 실패, 홈·로그인 axe 자동 접근성 검사를 수행한다. 스크린샷·트레이스는 Git 제외 `test-results/`에 생성한다. 자동 접근성 검사는 전체 수동 접근성 심사를 대신하지 않는다.

## 구조와 계약

`src/api/client.js`는 타임아웃·오류·CSRF를 처리한다. `src/components`는 인증·공통 UI·레이아웃, `src/pages`는 업무 화면, `src/styles/main.css`는 반응형 스타일이다. [포털 API](docs/haedam/PORTAL-API.md), [계약 출처](contracts/README.md).

브라우저는 HttpOnly 쿠키를 사용하고 CSRF만 메모리에 둔다. 브라우저에 DB·대응 API 키를 전달하지 않는다. 미지정 경로는 배포 Flask에서 실제 404가 나며 무조건 SPA 200으로 바꾸지 않는다. Graylog·Wazuh·n8n·pfSense 실연동·두 PC 배포 검증은 후속 작업이다.

## 사용성 개선

민원 신청·담당자 답변 작성 중 이동·뒤로 가기·로그아웃은 계속 작성/작성 취소 선택을 먼저 받는다. 저장 중에는 화면 이탈을 진행할 수 없고, 저장 성공 후에는 결과로 정상 이동한다. 새로고침·탭 닫기는 브라우저의 기본 경고를 사용한다. 서버 자동 임시저장은 제공하지 않으며, 모바일 앱 강제 종료나 세션 만료까지 작성 내용을 보존하는 기능은 아니다.

필드별 한국어 오류와 최소 글자 수 안내를 표시하고 첫 오류 입력란에 포커스를 옮긴다. 서버의 선택적 `error.fields`도 동일하게 처리한다. 민원 목록의 검색·분야·상태·페이지는 URL에 남겨 상세 왕복과 새로고침에서 복원한다. 민원 원문·비밀번호를 URL이나 브라우저 저장소에 넣지 않는다. 모바일 목록 제목·상태·입력 글씨를 확대했다.

적용한 계약 원본: capstone `d134c71a6a9ae941c149c969ca42884348197eba`. 계약 사본 8개와 해시는 [SOURCE.json](docs/SOURCE.json)에 고정했다. 공통 규칙 v3 원본은 `5e79d461d71e5f70c4daf0288572624a0962f817`이며 자세한 해시·초기 이력은 [SOURCE.json](docs/SOURCE.json)에 있다.
