# 해담 민원포털 UI 개선 · 2026-10-26

사용자 요청으로 기존 화면을 검토하고 프론트 디자인을 개선했다. 브랜치 `codex/portal-design-1026`, 기준 frontend main `a98c0e5`. Windows·Edge에서 형제 Flask 백엔드와 일회용 SQLite로 확인한 집 작업이며 학원 VM 배포는 수행하지 않았다.

## 검토와 개선

| 기존 화면에서 확인한 점 | 적용한 개선 |
| --- | --- |
| 10~13px 보조/본문과 비슷한 색의 요소가 많아 행동 우선순위가 약함 | 제목·본문·입력·버튼의 계층을 재정리. 데스크톱 입력15px, 모바일16px, 주 버튼48px. 키보드 포커스·오류/상태 배지는 유지 |
| 홈의 신청만 강조되고 조회 동선이 분산됨 | 첫 화면에 신청/조회 두 행동을 나란히 배치. 청록색 도시 영역과 밝은 행동 영역을 구분 |
| 분야 이름만으로 접수 분야를 선택해야 함 | 6개 분야에 짧은 생활 예시를 추가하고 카드 전체를 기존 신청 경로로 연결 |
| 담당자·관리자 홈에 시민 신청 링크가 남음 | 실제 서버 역할에 따라 업무/계정 바로가기 제공. 시민 전용 신청 카드는 직원/관리자 홈에서 제외. 서버 권한을 대신하는 기능이 아님 |
| 로그인 그림과 홈의 인상이 다름 | 기존 도시 SVG를 CityScene 컴포넌트로 추출해 공유. 로그인 안내와 실제 폼을 분리 |
| 모바일에서 바로가기 설명이 사라지고 세로 카드만 남음 | 설명·화살표가 보이는 가로 행으로 정리. 320px에서는 첫 화면의 버튼을 세로 배치 |
| 좁은 로그인에서 문장이 붙고 한 글자가 마지막 줄에 남음 | 명시적인 줄바꿈과 레이아웃 간격을 복원하고 실제 390px 화면으로 재확인 |
| 관리자 표의 관리 메뉴가 좁은 화면 오른쪽에 위치 | 좌우 이동 안내와 포커스 가능한 이름 있는 스크롤 영역 제공. 표의 기능과 데이터는 유지 |

임의 처리 건수·성공률·공지·미구현 검색 같은 표시를 추가하지 않았다. 실제 최근 민원·상태 집계·검색·신청·답변을 그대로 사용한다. 외부 이미지/CDN/폰트·추가 런타임 의존성은 없다.

## 학원 반영과 남은 확인

1. 이 frontend 브랜치를 리뷰한 뒤 배포할 소스 커밋을 확정한다. 원격 PR 생성·main 병합·실제 사이트 배포는 이번 작업에서 하지 않았다.
2. A가 배포할 dist를 정상 빌드한다. 현재 학원 웹 루트 기록은 `/home/haedam/haedam-portal-frontend/dist`이며 실제 실행 경로를 다시 확인한다.
3. **A/C가 정상 배포 구간을 조율하고 FIM 기준본·해시 목록을 갱신한다.** 기존 117 기준본은 이전 frontend a98c0e5이므로 새 정적 파일을 변조로 오인하거나 원복으로 옛 디자인을 덮지 않도록 한다. 이 집 작업은 학원 파일/기준본을 수정하지 않았다.
4. VM에서 로그인→접수→직원 처리→시민 답변과 미지정 경로404, 실제 모바일 브라우저를 확인한다. 이번 UI 변경에서 MySQL·실제 두 PC/VPN·Graylog/Wazuh/n8n 연동은 재검증하지 않았다.

## 추가 검토 · 사용자가 화면을 보는 동안

- 실제 브라우저에서 비로그인 홈의 환경·청소 카드를 선택→로그인→민원 신청을 따라가니 분야가 빈 값으로 돌아갔다. Guard가 복귀 주소의 pathname만 저장해 category 쿼리를 버리는 문제였다(기존 동작). pathname+search를 보존하도록 수정하고, 실제 로그인 후 선택값/URL을 확인하는 회귀를 추가했다. API·서버 권한 변경은 없다.
- 홈/로그인/가입과 시민 목록·작성·계정, 직원 홈·업무, 관리자 홈·계정을 390/1440px에서 추가 axe 검사했다. **20개 화면 조합 모두 자동 검사 위반0**. 합성 계정·일회용 SQLite를 사용했고 관리자 상태 변경·실제 서비스/방화벽 호출은 하지 않았다.
- 검토 범위에서 추가 배포 차단 결함은 발견하지 못했다. 장기적으로 main.css와 refresh.css의 겹치는 규칙은 정리할 여지가 있지만, 현재 레이아웃/반응형/접근성 검증이 통과했으므로 이번 검토에서 큰 CSS 재구성은 하지 않았다.
- 로컬 미리보기는 127.0.0.1:5005로 사용자가 볼 수 있게 실행했다. 교육용 계정과 임시 DB만 사용하며 프로세스가 끝나면 데이터가 사라진다. 테스트 출력·접근성 상세는 Git 제외 .local/ui-review-1026에 있다.

추가 수정 후 npm run build 및 전체 브라우저 회귀 **14 passed(35.3초)**. 로그인 전 선택한 분야 유지 검사를 포함한다.

## 추가 개선 · 수업 Flask 게시판 참고

수업 저장소의 요약 카드→분포→목록 구조와 관리자 작업 구분을 참고했다. 개인 flask-board는 origin/main d180196까지 fast-forward(6커밋), 팀 게시판 origin/main 74fbb64는 이미 최신이었다. 참고 코드와 저장된 10/13 화면을 대조했으며 기존 게시판 운영 DB/보안 서비스를 실행하지 않았다.

관리자 화면에 청록색 제목 영역, 계정 관리 안내와 별도 관제 서비스 영역, 현재 페이지 권한별 요약 카드, 계정 목록을 배치했다. 카드와 잠금 필터는 **현재 API 페이지의 계정만** 좁힌다. 전체 검색 결과 수와 현재 페이지 집계/표시 수를 구분하고 검색·페이지 이동·초기화 시 페이지 내 조건을 해제한다. API가 제공하지 않는 전체 권한별 통계를 만들어 표시하지 않는다. 서버 권한·잠금·세션·비밀번호 정책과 관제 서비스 분리는 유지했다.

검증: build/Prettier/diff 통과. 실제 Flask/Waitress·새 임시 SQLite·Edge E2E **15 passed(36.6초)**. 기존 사용자의 5005 미리보기와 데이터를 보존하기 위해 검증 서버를 5006에 별도로 시작하고, Git 제외 복사 테스트에서 baseURL만 5006으로 치환했다. 새 회귀는 권한 카드 필터, 검색 시 필터 해제, 빈 결과, API 실패 시 요약 숨김과 재시도를 확인했다. 두 화면×5폭(320/390/768/1024/1440) 총10개 넘침/JS 검사 통과, 390/1440px axe4조합 위반0. 관리자 제목 설명의 대비 문제를 고치고 재검사했다. 자동 검사는 전체 수동 접근성 감사가 아니다.

로컬 캡처/보고서: `.local/board-reference-1026/`. 사용자 브라우저의 5005 관리자 화면을 새 빌드로 갱신했으며 계정·민원을 초기화하지 않았다. 학원 VM·MySQL·운영 FIM 기준본은 미검증이며 정상 배포 후 A/C 대조가 필요하다. 향후 개선 후보는 민원 진행 단계/다음 행동 표시, 관제의 대응 실패·효과 미확인 우선 조회, 시연용 증적 내보내기다. 현재 구현 완료 항목과 구분한다.

## 세 권한별 업무 흐름 개선 · 시민/담당자/관리자

사용자가 세 권한 화면을 모두 개선할 것을 명시했다. ‘지원’은 기존 담당자(직원) 권한으로 해석해 해당 업무 화면을 수정했다. 범위는 Home/Petitions/PetitionDetail/Admin, 새 PetitionJourney와 workflows.css이며 API·DB·백엔드·보안 대시보드 자체는 변경하지 않았다.

- 시민: 목록에 결과 확인 안내와 완료 민원 필터를 추가했다. 상세의 접수 완료→담당자 배정→처리 중→답변 완료 단계는 서버의 status와 assignee로만 계산한다. 예정 단계의 가짜 시각/소요시간/처리 완료를 표시하지 않는다. 완료된 민원의 답변 바로가기를 제공한다.
- 담당자: 역할에 맞는 홈 제목·설명, 배정/처리/답변 안내, 진행 중 업무 필터를 추가했다. 각 목록 항목은 서버 상태에 따라 배정하기/처리 시작하기/답변 작성하기/처리 기록 확인으로 연결한다. 링크는 상세를 열며 실제 상태 변경은 기존 API와 동시성/권한 검사 후 이뤄진다. 미배정과 접수 상태를 혼동하지 않는다.
- 관리자: 역할별 홈, 계정 찾기→작업 선택→변경 내용 확인 안내, 변경 대상 이름/아이디/현재 역할 및 저장 전후 미리보기를 추가했다. 권한 선택 시 미리보기가 바뀌며 실제 반영은 저장 성공 후에만 표시된다. 잠금·비밀번호 재설정·기존 세션 회수 정책은 바뀌지 않았다.
- 공통: 민원 카드 집계는 권한 범위 전체이고 검색·분야와 별도임을 명시했다. 로딩/조회 실패 중에는 과거 숫자를 새 결과처럼 보여 주지 않는다. 새 스타일은 workflows.css로 분리해 기존 refresh.css에 계속 누적하지 않았다.

검증: build/Prettier/diff 통과. 실제 Flask/Waitress·새 임시 SQLite·Edge **15 E2E(24.9초)**. 기존 시민→담당자→시민 시나리오에 서버의 실제 배정/처리/완료 이후 각 단계와 답변 바로가기 검증을 추가했고, 관리자 권한 변경과 잠금의 변경 전후 표시를 검증했다. 변경 후 빌드의 CSS/JS 해시를 유지한 스타일 파일 분리도 빌드로 확인했다.
