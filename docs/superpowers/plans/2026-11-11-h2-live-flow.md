# H2 Live Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run H2 from the practice panel through portal denial events, Graylog detection, n8n response, ticketing, verification, and approved restoration.

**Architecture:** H2 will preserve the portal's existing access-control behavior: a citizen receives 403 only for existing petitions owned by another citizen. The panel creates isolated victim/attacker data and produces three denied detail requests. Graylog aggregates by `username` and `src_ip`; an H2 n8n workflow records a ticket then applies the agreed account-lock and source-IP-block actions. Release restores only those actions and verifies the attacker can read their own petition while another citizen's petition remains 403.

**Tech Stack:** Flask portal, MySQL, Graylog 6.1, n8n, ticket-store API, Docker, Python/pytest.

**Spec:** `lab/h2/README.md`, `lab/h2/graylog/h2-petition-access-denied.json`, `docs/검증-체크리스트.md` H2 section.

## Global Constraints

- H2 uses only fresh local synthetic citizens and petitions; it never reads or changes unrelated petitions.
- A missing or unauthorized release request must not unlock an account or unblock an IP.
- Plain passwords, response keys, session values, and webhook credentials must not be committed or written to evidence.
- The currently committed Graylog definition remains a draft until it is imported, linked to its notification, enabled for a controlled run, and restored afterward.
- The panel must reject a direct H2 action until all H2 runtime dependencies are registered and health-checked.

## Review Focus

- Three denied requests must target three distinct existing petitions owned by another citizen; 404s and self-owned 200s do not count.
- Aggregation must separate different `username`/`src_ip` pairs and use a five-minute window with `count() > 2`.
- n8n must reject malformed or protected-source input before ticketing or action.
- Release must restore only the H2 ticket's account and IP actions, not a different active incident.
- The panel must surface a failed import, notification, or action as an error rather than presenting a completed response.
