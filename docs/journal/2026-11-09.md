## pfSense 컨테이너 (Task 1)

- **WSL2 설정:** `.wslconfig`에 `memory=12GB`와 `vm.max_map_count`를 넣었다. `docker info` 기준으로 메모리 약 12.5GB, CPU 16개가 잡힌다.
- **KVM:** `docker run --device /dev/kvm alpine ls -l /dev/kvm`이 성공했다. Docker Desktop(WSL2) 안에서 KVM을 쓸 수 있다는 뜻이고, 그래서 pfSense VM을 하드웨어 가속으로 돌린다.
- **설계상 고민(포트 게시):** 컨테이너의 wan/lan NIC는 VM에 넘기면서 IP를 지운다. 그러면 Docker가 호스트 포트(8006)를 지워진 IP로 보낼 위험이 있다. 그래서 설치 콘솔 전용 `console` 망을 따로 두고 `gw_priority: 100`으로 기본 망을 지정했다.
- **설계상 고민(NIC 순서):** Docker가 붙이는 NIC 순서는 보장되지 않는다. 그래서 entrypoint가 인터페이스 이름 대신 IP 대역(203.0.113.*, 10.250.0.*)으로 wan/lan을 찾는다.

### 문제 1: 웹 UI가 잠깐 되다가 끊김

- **증상:** 첫 로그인 직후 `127.0.0.1:8443`이 시간 초과됐다. VM 콘솔은 멀쩡했고 로그인 성공 로그도 있었다.
- **원인:** 컨테이너 안 `br-taplan`의 MAC 테이블에 VM MAC(`52:54:00:00:02:01`)이 `taplan`이 아니라 바깥 포트 `eth0`에 학습돼 있었다. Docker 쪽이 VM의 브로드캐스트를 되돌려 보내면서 생긴 일로 보인다. 그래서 VM으로 갈 프레임이 도로 밖으로 나갔다.
- **조치:** 바깥 포트를 `learning off`로 바꿨다. 처음엔 entrypoint에서 `bridge link set ...`을 불렀는데, entrypoint에 같은 이름의 셸 함수 `bridge()`가 있어 그 함수가 호출되며 재시작이 반복됐다. `command bridge`로 고쳤다.

### 문제 2: 포트 포워드는 되는데 연결이 RST로 끊김

- **증상:** `normal`(203.0.113.100)에서 `203.0.113.1:80`으로 연결하면 실패했다. pfSense는 SYN을 `10.250.0.2:5000`으로 정상 포워딩했다(tap 캡처로 확인).
- **원인:** Docker 호스트의 `-s 203.0.113.0/24 ! -o <wan 브리지> -j MASQUERADE` 규칙이 `br_netfilter` 때문에 lan 브리지를 지나는 프레임에도 걸렸다. 출발지가 `10.250.0.254`로 바뀌어 nginx가 pfSense가 아닌 호스트로 답했고, 호스트가 그 답을 wan으로 바로 보내 클라이언트가 RST를 보냈다.
- **조치:** wan 망만 `enable_ip_masquerade: "false"`. 출발지 보존이 과제의 핵심이라 wan 컨테이너의 인터넷 접근을 포기했다.

### 문제 1: bootstrap이 끝나지 않음

- **원인:** 기동 대기에 쓴 `/api/system/lbstatus`는 `text/plain`을 돌려줘서 `Accept: application/json` 요청이 실패했고, 대기 루프가 그 실패를 "아직 안 뜸"으로 보고 계속 기다렸다.
- **조치:** JSON을 주는 `/api/system`으로 바꿨다.

### 문제 2: 파이프라인 문법 오류

- **원인:** 팀 내보내기 파일은 한 단계의 규칙을 `rule "a", "b"`로 이어 적었지만, Graylog API는 `rule "a";`를 한 줄에 하나씩 받는다.
- **조치:** 파서가 단계 줄을 나눠 쓰도록 바꾸고 테스트에 넣었다.

### 문제 3: pfSense 차단 로그가 검색에 안 잡힘

- **증상:** 파이프라인은 정상(`rule:pfsense-block`, `src_ip` 203.0.113.22)인데 최근 15분 검색에 0건.
- **원인:** pfSense BSD syslog는 시간대 없이 한국 시각을 보낸다. Graylog가 UTC로 해석해 메시지가 9시간 미래로 저장됐다.
- **조치:** Syslog 입력 설정에 `timezone: Asia/Seoul`. 이미 있는 입력도 bootstrap이 설정을 맞춘다. pfSense 원격 syslog는 Graylog 입력 포트에 맞춰 514에서 1514로 바꿨다.
