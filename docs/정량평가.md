## 지표 정의

| 지표 | 정의 |
| --- | --- |
| 자동 대응 | 사람 개입 없이 기대한 조치(S10은 포털+pfSense 차단, S8·S1은 포털 차단, H1은 포털 작성 제한)가 모두 적용되고, 공격자 거부(S10·S8·S1은 403 또는 연결 실패, H1은 작성 429)와 `normal` 정상(H1은 작성 201, 나머지는 200)이 함께 확인된 회차 |
| 원복 | `--restore` 해제 뒤 공격자 요청이 정상 사용자와 같은 결과(H1은 작성 201, 나머지는 200)로 돌아온 회차 / 원복 시도 |
| 정상 사용자 영향 | 대응 중 `normal`(`203.0.113.100`)의 요청이 정상(H1은 작성 201, 나머지는 200)이 아니었던 회차 수 |
| 오탐(기준선) | `--baseline` 회차(정상 사용 속도 입력, H1은 2분 간격 3건) 중 티켓이 생긴 회차 / 기준선 회차 |
| MTTD | Graylog 이벤트의 조건 충족 시각(`event.timestamp`) → 탐지 처리 시각(`timestamp_processing`) |
| 탐지→차단 | 탐지 처리 시각 → 마지막 차단 조치 완료 |
| 입력→차단 | 실행기가 공격 입력을 시작한 시각 → 마지막 차단 조치 완료. Graylog 1분 평가 주기가 포함된 체감 시간 |

위 표와 "전체"는 원인을 고친 뒤의 회차만 셉니다. 수정 전 실패 회차는 그 아래 표에 따로 셉니다. 중앙값은 자동 대응에 성공한 회차만으로 계산합니다. 정량평가는 케이스 실측이 모두 끝난 뒤에만 반영합니다.

- **자동 대응 13/13, 원복 13/13(수정 후):** 위 표와 "전체"는 원인을 고친 뒤의 회차만 센다. 수정 전 실패 5회는 아래 표에 따로 둔다.
  - **S10 수정 전 2회:** 1회차는 pfSense 대응 도구가 `easyrule` 반영(약 2초) 전에 결과를 읽어 `outcome_needs_reconciliation`을 냈고, 2회차는 자동 대응은 성공했지만 해제 워크플로가 pfSense 해제 성공(`applied_verified:false`)을 오류로 읽어 멈췄다. 두 곳 모두 pfSense 경로라 S8·S1에는 영향이 없다.
  - **H1 수정 전 3회:** 탐지와 n8n 호출은 정상이었지만 티켓 저장소 검증 목록에 `H1`이 없어 기록이 400으로 거부됐고, 기록 실패 시 조치하지 않는 규칙에 따라 작성 제한도 걸리지 않았다(원복 시도 없음).
  - 06:11 UTC에 손으로 한 번 더 돌린 S10 회차는 어느 표에도 넣지 않았다. 티켓 저장소만 비운 상태라 티켓 번호(`T-20261109-0001`)가 1회차와 겹쳤고, pfSense 대응 도구가 남아 있던 1회차 기록을 같은 요청의 재전송으로 보고 거부했다(`replay_needs_reconciliation`). 환경 상태 문제라 지표에 넣지 않았고, 같은 충돌이 다시 나지 않게 고쳤다. 경위는 [S10 티켓](tickets/S10/README.md)과 [작업 일지](journal/2026-11-09.md).
- **정상 사용자 영향 0회:** 수정 전후 18회 모두 대응 중 `normal`(`203.0.113.100`)은 200이었고, S1에서는 공격받은 계정의 주인이 같은 계정으로 정상 로그인(200)했다.
- **MTTD는 팀 값과 직접 비교하지 않는다.** 이 표의 MTTD는 Graylog 이벤트 안의 두 시각(조건 충족→처리) 차이라 0.5초 안팎이다. 팀 리포트의 51.4초는 평가 주기(1분)를 포함한 값으로 보이며, 이 PC에서 같은 성격의 값은 **입력→차단 중앙값 31.0초**(S10 35.5·S8 30.5·S1 18.2·H1 41.7초)다. 팀 리포트가 조건 충족 시각을 무엇으로 잡았는지는 이 저장소에서 확인하지 못했다.
- **입력→차단이 팀보다 짧은 이유(추정):** 한 PC 안의 Docker 네트워크라 팀 VPN 왕복이 없고, 포털 로그를 GELF TCP로 보내 유실·재전송이 없다. 남은 지연은 대부분 Graylog의 1분 평가 주기에서 온다(입력 시점에 따라 0~60초). S1이 짧은 것은 실패 로그인 9회를 보내는 동안 이미 주기가 지나가기 때문이다.
- **표본이 작다:** 티켓마다 3~5회라 중앙값은 경향만 보여 준다. 오탐 기준선은 H1 1회(정상 시민 속도: 2분 간격 3건)뿐이고 티켓이 생기지 않았다(0/1).
