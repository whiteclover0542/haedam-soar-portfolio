## 지표 정의

| 지표 | 정의 |
| --- | --- |
| 자동 대응 | 사람 개입 없이 기대한 조치(S10은 포털+pfSense 차단, S8·S1은 포털 차단, S4는 포털 계정 잠금, S12는 포털 출발지 차단, H1은 포털 작성 제한, H2는 포털 계정 차단+잠금, H3는 담당자 계정 잠금)가 모두 적용되고, 공격자 거부(S10·S8·S1·H2는 403 또는 연결 실패, H1은 작성 429, S4는 맞는 비밀번호 로그인 401, S12는 출발지 403, H3는 담당자 로그인 401)와 `normal` 정상(H1은 작성 201, H3는 신청자 민원 3건이 모두 변경 전 상태로 복원돼 200, 나머지는 200)이 함께 확인된 회차 |
| 원복 | `--restore` 해제 뒤 공격자 요청이 정상 사용자와 같은 결과(H1은 작성 201, 나머지는 200)로 돌아온 회차 / 원복 시도. S4는 비밀번호 재설정 뒤 계정 주인의 새 비밀번호 로그인, S12는 차단 해제 뒤 출발지 200, H3는 관리자 해제 뒤 담당자 로그인 |
| 정상 사용자 영향 | 대응 중 `normal`(`203.0.113.100`)의 요청이 정상(H1은 작성 201, 나머지는 200)이 아니었던 회차 수 |
| 오탐(기준선) | `--baseline` 회차(정상 사용 속도 입력, H1은 2분 간격 3건, H2는 타인 민원 거부 2건, S12는 0.5 req/s 60초, H3는 담당자 민원 변경 2건) 중 티켓이 생긴 회차 / 기준선 회차 |
| MTTD | Graylog 이벤트의 조건 충족 시각(`event.timestamp`) → 탐지 처리 시각(`timestamp_processing`) |
| 탐지→차단 | 탐지 처리 시각 → 마지막 차단 조치 완료 |
| 입력→차단 | 실행기가 공격 입력을 시작한 시각 → 마지막 차단 조치 완료. Graylog 1분 평가 주기가 포함된 체감 시간 |

위 표와 "전체"는 원인을 고친 뒤의 회차만 셉니다. 수정 전 실패 회차는 그 아래 표에 따로 셉니다. 중앙값은 자동 대응에 성공한 회차만으로 계산합니다. 정량평가는 케이스 실측이 모두 끝난 뒤에만 반영합니다.

"공격자"는 차단된 출발지(403), "normal"은 정상 시민 `.100`(200)이다. MTTD(5.6초)와 탐지→차단(4.5초)이 다른 케이스보다 긴 것은, 차단 전에 health 표본 3회(각 2초)를 사용자 영향 근거로 수집하기 때문이다(차단 판정 자체는 요청 수 기준). 팀 설계는 health가 2초를 3회 연속 넘을 때만 차단해 팀 실측(1회)에서 차단 경로를 관측하지 못했으나, PC 한 대에서는 부하로 health가 느려지지 않아 요청 수 기준(`count_based`)으로 바꿔 차단 경로를 확인했다. 상세는 [S12 티켓](tickets/S12/README.md).

"공격자"는 잠금 뒤 맞는 비밀번호 로그인(401), 원복은 비밀번호 재설정 뒤 계정 주인의 새 비밀번호 로그인(200)이며 옛 비밀번호는 계속 401이다. 공격자가 쥐고 있던 세션은 매 회차 401로 끊겼다. 팀 S4-after-01(1회)의 성공→잠금 6.975초와 비교하면 이 PC는 6.4~24.1초(중앙값 15.7초)인데, 차이는 대부분 1분 평가 주기에서 온다(탐지→잠금은 0.6초 안팎으로 팀 0.979초와 비슷). 상세는 [S4 티켓](tickets/S4/README.md).

"공격자"는 잠긴 담당자 로그인, "normal"은 신청자의 민원 3건(모두 복원돼야 200), 원복은 관리자 해제 뒤 담당자 로그인 200이다. Graylog 집계 경보에는 `petition_id`가 남지 않아 n8n은 담당자 이름만 넘기고 포털이 대상을 찾는다. MTTD는 Graylog 시각을 티켓에 넘기도록 고친 뒤 2회만 측정됐다. 상세는 [H3 티켓](tickets/H3/README.md).
- **정상 사용자 영향 0회(수정 후):** 수정 후 25회 모두 대응 중 정상 사용자(`203.0.113.100`, H3는 민원 신청자)는 정상이었다. 수정 전에는 H3 1회에서 신청자 민원 2건이 조작된 채 남았다. S1에서는 공격받은 계정의 주인이 같은 계정으로 정상 로그인(200)했다.
