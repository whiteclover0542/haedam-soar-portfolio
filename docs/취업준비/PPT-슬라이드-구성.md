# 해담 SOAR 포트폴리오 PPT 구성

> 목적: 발표자료 제작 전, 슬라이드 순서와 각 장에 들어갈 증적을 정리한다.
> 원칙: 수치·화면·결과는 실제 확인한 자료만 넣는다.

## 제작 기준 (2026-11-11 최종)

- 발표본: [해담-SOAR-포트폴리오-발표본-2026-11-11-r4.pptx](해담-SOAR-포트폴리오-발표본-2026-11-11-r4.pptx)
- 발표 대상: 보안 자동 대응을 짧게 시연하고 구현 근거를 확인하려는 평가자
- **넣을 실측 범위(완료 7종):** S10·S8·S1·S4·H1·H2·H3. S12는 요청 수 기준 차단으로 1회 이상 확인(가용성). **S7은 보류**(팀도 보강 후 실제 회차 없음, 포털 컨테이너 Wazuh 에이전트 필요) — 발표에서는 "이번 범위 밖"으로 솔직히 표기.
- **핵심 수치:** 수정 후 자동 대응 25/25, 원복 25/25, 정상 사용자 영향 0회, 기준선 오탐 0/9, 입력→차단 중앙값 34.7초.
- **차별점(리뷰어 요구 대응):** 같은 케이스를 ① raw curl(프로젝트 코드 0) · ② 스크립트 · ③ 제어판 **세 진입점**으로 재현해 모두 같은 탐지→대응→원복이 돌았다. "제어판 전용 시연이 아니라 실제 방어 경로"라는 독립 증거.
- 권장 분량: 10~11장, 8~10분. 화면 캡처는 한 장에 하나만 크게 놓고 캡션으로 무엇을 증명하는지 설명한다.
- 증적 원본: [정량평가](../정량평가.md), [검증 체크리스트](../검증-체크리스트.md), 티켓별 `docs/tickets/<ID>/README.md`, `docs/captures/`.

## 캡처 반입과 가림 점검

- 캡처는 티켓별로 찍지 않고 PPT 단계(P-6)에서 한꺼번에 찍는다. 각 캡처에서 로그인 정보·API 키·세션 값·웹훅 URL의 키·비밀번호·토큰·Discord 개인정보를 가린다.
- 슬라이드 4~6(한 케이스 워크스루)과 8~9(결과·독립 재현)에 넣을 화면: Graylog 경보, n8n Executions(모두 Success), 티켓 대시보드(차단→restored), Discord 알림 카드.
- 원본 캡처는 `docs/captures/`에 보관하고, 파일명은 해당 티켓 ID와 맞춘다.
