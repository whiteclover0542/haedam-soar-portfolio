- 발표본: [해담-SOAR-포트폴리오-발표본-2026-11-12-r5.pptx](해담-SOAR-포트폴리오-발표본-2026-11-12-r5.pptx) (12장). r4까지는 이전 판.
- 발표 대상: 보안 자동 대응을 짧게 시연하고 구현 근거를 확인하려는 평가자
- **넣을 실측 범위(9종):** S10·S8·S1·S4·S7·S12·H1·H2·H3. S7은 2026-11-12(KST) 포털 컨테이너 Wazuh FIM → Graylog → n8n → Wazuh Active Response 자동 복구로 3/3 실측. Discord 수신만 웹훅 미설정으로 미검증 — 발표에서 그대로 밝힌다.
- **핵심 수치:** 수정 후 자동 대응 28/28, 원복 28/28, 정상 사용자 영향 0회, 기준선 오탐 0/10, 입력→차단 중앙값 34.77초, MTTD 중앙값 0.63초.
- **차별점(리뷰어 요구 대응):** 같은 케이스를 ① raw 명령(프로젝트 코드 0) · ② 스크립트 · ③ 제어판 **세 진입점**으로 재현해 9종 모두 같은 탐지→대응→원복이 돌았다.
- 권장 분량: 12장, 9~11분. 발표 전 1장의 `[이름 입력]`을 직접 채운다.
- 증적 원본: [정량평가](../정량평가.md), [검증 체크리스트](../검증-체크리스트.md), 티켓별 `docs/tickets/<ID>/README.md`, `docs/captures/`. 아직 없는 캡처는 [캡처 목록](../캡처-목록.md).

## 캡처 반입과 가림 점검

- 캡처는 티켓별로 찍지 않고 PPT 단계(P-6)에서 한꺼번에 찍는다. 각 캡처에서 로그인 정보·API 키·세션 값·웹훅 URL의 키·비밀번호·토큰·Discord 개인정보를 가린다.
- 슬라이드 4~6(한 케이스 워크스루)과 8~9(결과·독립 재현)에 넣을 화면: Graylog 경보, n8n Executions(모두 Success), 티켓 대시보드(차단→restored), Discord 알림 카드.
- 원본 캡처는 `docs/captures/`에 보관하고, 파일명은 해당 티켓 ID와 맞춘다.
