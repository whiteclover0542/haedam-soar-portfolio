## 프로젝트

### 해담시청 SOAR — 민원 포털 보안 자동 대응 | 2026.10 ~ 2026.11 | 4인 팀 프로젝트 후 개인 확장

- **목적:** 민원 포털에 대한 공격을 탐지하고, 티켓 기록·자동 차단·원복까지 한 흐름으로 연결
- **팀에서의 역할:** 포털 서비스와 대응 API, 로그인 공격 케이스(S1·S4) 담당
- **개인 확장:** 팀 결과물을 Docker Compose 한 벌로 재구성하고, 새 시나리오 4종(H1·H2·H3·S12)을 추가해 8종을 직접 실측
- **기술:** Python(Flask), Graylog, n8n, pfSense, Wazuh, Docker Compose, MySQL
- **링크:** https://github.com/whiteclover0542/haedam-soar-portfolio

**결과 (수정 후 실측, PC 한 대 기준)**

| 지표 | 값 |
| --- | --- |
| 자동 대응 성공 | 25/25 (8개 시나리오) |
| 원복 성공 | 25/25 |
| 대응 중 정상 사용자 영향 | 0회 |
| 정상 사용 기준선에서의 오탐 | 0/9 |
| 입력부터 차단까지 (중앙값) | 34.7초 |

**기여**

- **가용성·기밀성·무결성 시나리오를 설계하고 실측했습니다.** 민원 도배(H1), 타인 민원 엿보기(H2), 처리 결과 조작(H3), 요청 폭주(S12)를 각각 포털 변경 → 탐지 정의 → 대응 워크플로 → 기준선 → 실측 3회 순서로 완성했습니다.
- **대응 범위를 공격에 맞게 좁혔습니다.** 무차별 대입은 출발지만, 민원 도배는 그 계정의 작성 기능만, 계정 탈취는 계정과 세션만 막도록 해 25회 모두 정상 사용자 요청이 그대로 처리됐습니다.
- **실측으로 결함을 찾아 고쳤습니다.**
  - 처리 결과 조작(H3) 대응이 바뀐 민원 3건 중 마지막 1건만 되돌리는 것을 확인하고, 해당 담당자가 최근 바꾼 민원을 모두 변경 전 상태로 되돌리도록 고쳤습니다(수정 후 3/3).
  - 민원 도배(H1) 탐지는 됐는데 티켓이 남지 않는 원인을 티켓 저장소의 허용 목록 누락으로 좁혀 고쳤습니다(수정 전 0/3 → 수정 후 3/3).
  - 요청 폭주(S12)는 팀 설계(응답 지연 기준)로는 차단 경로가 한 번도 실행되지 않아, 요청 수 기준으로 바꿔 차단과 해제를 확인했습니다.
- **제어판 시연에만 기대지 않았습니다.** 같은 공격을 raw `curl`, 스크립트, 제어판 세 경로로 재현해 모두 같은 탐지·대응·원복이 이어지는 것을 확인했습니다.
- **실패 회차를 숨기지 않고 따로 집계했습니다.** 수정 전 실패 9회는 원인·수정과 함께 별도 표로 남겼습니다.
