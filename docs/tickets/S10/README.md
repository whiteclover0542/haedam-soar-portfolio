# S10 경계 차단 · 포털 스캔 · 로그인 반복

- **원작:** B — 탐지 정의 `lab/s8s10/graylog/s10-three-layer.json`, 입력 도구 `tools/s8s10_input.py`, pfSense 대응 도구 `lab/pfsense/`
- **이 PC에서 보는 것:** 서버(포털)·Graylog·pfSense·n8n·티켓 저장소가 한 번에 맞물리는지

## 시나리오

| 단계 | 내용 |
| --- | --- |
| 입력 | `203.0.113.22`가 `GET /_zz_s8s10_<id>`(404) → `GET /api/v1/auth/me`(200, CSRF) → `POST /api/v1/auth/login`(401) → `ping 203.0.113.1`(pfSense 기본 차단) |
| 탐지 | Graylog 정의 "S10 경계 차단·스캔·로그인 반복": 15분 안에 같은 `src_ip`의 `pfsense-block`·`web-scan`·`login-bruteforce`가 모두 나타남(`card(rule) > 2`), 1분마다 평가 |
| 대응 | n8n `haedam-32` → 포털 IP 차단(`haedam-12`) + pfSense 차단(`haedam-14`, SSH forced command) → 티켓 기록(`haedam-10`) |
| 효과 | 공격자 `.22`는 pfSense에서 연결 자체가 막힘(`000`), `normal`(`.100`)은 200 |
| 원복 | `haedam-50`: pfSense 해제 → 포털 해제 → 공격자 200, 티켓 `restored` |

같은 입력이 S8 정의(`card(rule) > 1`)도 발동시키므로 포털 차단은 두 번 기록됩니다(두 번째는 `already_applied` 또는 같은 결과).

## 실행

```powershell
python lab/run_ticket.py S10 --restore
```

기대 출력의 핵심 필드: `"result": "pass"`, `effect.attacker` `"000"`, `effect.normal` `"200"`, `restore.steps` `[[1, "released"], [2, "released"]]`, `restore.attacker_after` `"200"`.
