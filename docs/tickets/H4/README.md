# H4 · 담당자 대량 조회 대응 (기밀성 · 내부자)

민원 담당자 계정이 짧은 시간에 시민 민원 상세를 대량으로 여는 경우입니다. 담당자는 원래 민원을 볼 권한이 있으므로 403 같은 거부 신호가 없습니다. 그래서 **정상 권한 안의 과도한 사용량**을 기준으로 탐지합니다.

## 흐름

```text
담당자 GET /api/v1/petitions/<id> ─▶ 포털 이벤트 petition.viewed(username, petition_id)
   ─▶ Graylog "H4 staff bulk petition view": 같은 username 10분 안에 20건 이상(count() > 19, 1분 평가)
   ─▶ n8n haedam-38 ─▶ 티켓 detected ─▶ haedam-13 계정 잠금(세션 회수) ─▶ 티켓 applied ─▶ Discord
   ─▶ 관리자가 조회 목적 확인 뒤 /admin/users/<id>/unlock ─▶ haedam-50이 잠금 해제를 확인하고 티켓 restored
```

- 포털 변경: 담당자(staff)가 민원 상세를 열 때만 `petition.viewed`를 남깁니다. 시민의 자기 민원 조회는 남기지 않습니다(포털 테스트 `test_staff_detail_view_is_logged_for_h4_but_citizen_view_is_not`).
- 대응은 설계 초안의 "역할 강등" 대신 **계정 잠금(세션 회수)** 으로 했습니다. 포털에 역할 변경 대응 API가 아직 없고, 잠금은 H3·S4에서 검증된 경로라 같은 원복(관리자 해제) 절차를 씁니다. 역할 강등은 후속 과제입니다.
- 임계값 N=20(10분): 기준선은 담당자가 민원 8건을 연달아 여는 정상 업무 속도이며 티켓이 생기지 않았습니다.

## 실측 방법

```powershell
python infra/graylog/bootstrap.py --live
python infra/n8n/load.py --h4            # 또는 전체 load.py
python lab/h4/live.py                    # 실측 1회
python lab/h4/live.py --baseline         # 기준선(8건 조회 → 티켓 없어야 pass)
```

- 회차마다 새 `zz_h4_staff_…` 담당자와 시민을 만듭니다. 담당자가 열 수 있는 민원(미배정·본인 배정)이 25건보다 적으면 시민 계정 여러 개가 4건씩 등록해 채웁니다(H1의 5건 조건 아래).
- "공격자" 열: 잠긴 담당자의 새 로그인(401). 쥐고 있던 세션도 401로 끊겼는지 `session_after_lock`에 남깁니다.
- "normal" 열: 시민이 자기 민원을 조회(200).
- "해제 후 공격자" 열: 관리자 해제 뒤 담당자 로그인(200). 티켓은 haedam-50이 `restored`로 닫습니다.
- 권한: 키 없는 해제 웹훅 호출 403.
- 회차 사이 5분: 실행기가 호스트(127.0.0.1)에서 관리자·시민·담당자로 여러 번 로그인하므로 포털의 출발지별 로그인 한도(5분 20번)를 넘지 않게 합니다.

## 수정 전 실패 1회

`T-20261111-0012`(18:40 UTC): 탐지·티켓·계정 잠금은 됐지만(새 로그인 401·세션 401·시민 200), 잠금 결과를 티켓에 기록하는 요청이 `400 VALIDATION_ERROR`(Idempotency-Key 8~100자)로 거부됐습니다. 워크플로가 키를 `<n8n 실행 번호>-lock`으로 만들었는데, 이 PC의 n8n은 DB를 새로 만들어 실행 번호가 두 자리(`87-lock`, 7자)였습니다. H3(`haedam-37`)도 같은 키라 새 n8n에서는 같은 문제가 납니다. 두 워크플로 모두 `-lock-1`로 바꾸고, 모든 워크플로의 키가 실행 번호 한 자리에서도 8자 이상인지 보는 테스트(`test_idempotency_keys_stay_valid_for_a_one_digit_execution_id`)를 추가했습니다. 정량평가에서는 이 회차를 수정 전 표에 따로 셉니다.

## 한계

- 탐지 기준은 조회 건수뿐입니다. 근무 시간 외 가중치, 담당 분야 밖 민원 비율 같은 신호는 아직 없습니다.
- 대응은 계정 잠금이라 해당 담당자의 정상 업무도 함께 멈춥니다. 관리자 확인이 빨라야 합니다.
